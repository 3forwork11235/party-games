# SPEC: Элитный бильярд (`elite-billiards`)

> Всё, что не указано, — из `DEFAULT_GAME_CONFIG` и общих правил движка.

## 1. Концепция

- Питч: классический пул сверху, но шары **разного размера и массы**: маленький лёгкий шар разлетается от любого касания, гигант еле сдвигается и едва пролезает в лузу. Забивай — получай очки по номиналу шара.
- Социальный момент: все смотрят каждый удар в реальном времени, видят прицел стрелка, стонут на «почти-заходах» гиганта в лузу.
- Жанр: бильярд (пул) на очки, по очереди.

## 2. Игроки

- min / max: **2 / 8**. Ролей нет. Порядок ходов — `order` (порядок входа), задаётся в `onGameStart`.
- Раунд = одна раскладка. Первый стрелок раунда r — `order[(r-1) % n]` (пропуская отключённых).
- Выход посреди раунда: ход отключённого пропускается; если ушёл стрелок в стадии aim — ход переходит дальше без штрафа. < 2 подключённых → results (core).
- Вход после старта: нет.
- Боты: хост добавляет до 7 ботов в лобби (`maxBots`). Бот целится через «шар-призрак» в лузы, проверяет до 12 вариантов настоящей физикой и бьёт с небольшой ошибкой (TASKS G4).

## 3. Фазы и тайминги

`GameConfig`: rounds 3, countdownMs 3000, roundMs = `SHOT_MS` 35000 (таймер удара), roundEndMs 7000, idleKickSec 900.

| Фаза      | Длительность       | Что видит игрок                        | Что делает сервер | Выход                           |
| --------- | ------------------ | -------------------------------------- | ----------------- | ------------------------------- |
| lobby     | —                  | app-shell + правила                    | —                 | хост start                      |
| countdown | 3 с                | стол с новой раскладкой, «Раскладка N» | —                 | таймер                          |
| round     | стадии aim/rolling | стол, прицел, HUD                      | ходы, симуляция   | все шары забиты / `RACK_MAX_MS` |
| roundEnd  | 7 с                | scoreboard app-shell (+очки раскладки) | —                 | таймер                          |
| adBreak   | 1.5–30 с           | app-shell                              | core              | все `core:adDone`               |
| results   | —                  | подиум                                 | —                 | хост restart                    |

Стадии round (`state.stage`), таймер стадии — core `phaseEndsAt` через `restartRound(ms)`; `onRoundTimeout` всегда возвращает true:

- `aim` (SHOT_MS): стрелок целится. Удар → симуляция на сервере, `MSG_SHOT_PLAYED` всем, stage `rolling`, `restartRound(durationMs + ROLL_GRACE_MS)`. Таймаут → фол `timeout`, ход следующему.
- `rolling`: все проигрывают удар локально. Таймаут → сервер применяет итог (позиции, забитые, очки, фол, следующий стрелок), stage `aim`, `restartRound(SHOT_MS)`. Если прицельных шаров не осталось или `now ≥ rackEndsAt` — `endRound()`.

**Важно:** итог удара попадает в state только после rolling — состояние никогда не опережает анимацию.

## 4. Стол и шары (`shared/table.ts`, `shared/rack.ts`)

Игровое поле (по носам бортов) L = 2.54 × W = 1.27 м, начало — левый нижний угол, y вверх.

- Лузы: 4 угловые (0,0),(L,0),(0,W),(L,W) и 2 средние (L/2,0),(L/2,W). Индексы 0..5 в этом порядке.
- Створ угловой лузы CM = 0.118 м (по диагонали между губками) → борт начинается в c = CM/√2 от угла. Средняя SM = 0.128 м → борт прерывается на L/2 ± SM/2.
- Борта — 6 отрезков по носам: низ `y=0` [c, L/2−SM/2] и [L/2+SM/2, L−c]; верх `y=W` так же; лево `x=0` [c, W−c]; право `x=L` [c, W−c]. Концы отрезков — «губки» (столкновение с ближайшей точкой отрезка, т.е. с точкой-концом).
- Шар **забит**, когда его центр вышел за прямоугольник [0,L]×[0,W] (вне створов этого не допускают борта). Номер лузы — ближайшая из 6 точек.
- Дом (kitchen): x ≤ L/4. Точка битка — (L/4, W/2). Точка пирамиды — (3L/4, W/2).

| kind        | r, м   | номинал | кол-во в раскладке |
| ----------- | ------ | ------- | ------------------ |
| cue (биток) | 0.0286 | —       | 1                  |
| small       | 0.022  | 1       | 3                  |
| std         | 0.0286 | 2       | 3                  |
| big         | 0.035  | 3       | 2                  |
| giant       | 0.042  | 5       | 1                  |
| gold        | 0.0286 | 8       | 1                  |

Масса m = 0.17·(r/0.0286)³ кг. Самый большой (0.084 м) проходит в оба створа.
Раскладка: 10 прицельных шаров (id 1..10) — треугольник 4 ряда, вершина в точке пирамиды, ряды к +x; шаг D = 2·0.042 + 0.002, шаг рядов D·√3/2 (раскладка — не симуляция, Math.sqrt тут не важен). Шары перемешиваются RNG (функция `rng: () => number` параметром — тесты детерминированы), gold — всегда в центре 3-го ряда.

## 5. Физика (`shared/physics/*`, контракт — `physics/types.ts`)

Фиксированный шаг **DT = 0.001 с**, лимит 25 с. Только `+ - * /` и `Math.sqrt` (детерминизм сервер/клиент бит-в-бит). g = 9.81.

**Удар кием** (`strike`): v0 = 0.25 + power·(6.2 − 0.25) м/с; смещение (a, b) = (spinX, spinY), |(a,b)| ≤ MAX_TIP_OFFSET = 0.5 (клампится сохраняя направление). Направление d = (dx, dy), «право» = (dy, −dx).

- v = v0·d; ω_xy = (−dy, dx) · 2.5·b·v0/R (b = 0.4 — чистый накат, 0 — «стоп» со скольжением, < 0 — оттяжка); wz = 2.5·a·v0/R (a > 0 — правый винт, против часовой сверху).

**Сукно** (на каждый шар, не resting, не potted). Скорость точки касания u = (vx − R·wy, vy + R·wx).

- Скольжение, если |u| > 3.5·μs·g·DT: a = −μs·g·û; v += a·DT; wx += 2.5·a_y/R·DT; wy −= 2.5·a_x/R·DT. (u меняется ровно на 3.5·a·DT.)
- Иначе — переход в качение: v ← v − u·(2/7); wx = −vy/R; wy = vx/R.
- Качение: если |v| ≤ μr·g·DT → v = 0, иначе v −= μr·g·DT·v̂; затем wx = −vy/R, wy = vx/R.
- Винт: |wz| уменьшается на 2.5·μsp·g/R·DT до 0.
- μs = 0.2, μr = 0.012, μsp = 0.012.
- Покой: |v| < 0.004, |u| < 0.004 и |wz| < 0.6 → всё в 0, `resting = true`. Шар «просыпается» при любом импульсе.

**Порядок шага:** сукно → перемещение x += v·DT → лузы → шар-шар (все пары по возрастанию id, 2 прохода) → борта → проверка покоя. Симуляция закончена, когда все resting/potted.

**Шар-шар** (центры i<j, d < ri+rj, n = (pj−pi)/d):

- Позиционная коррекция всегда: перекрытие o = ri+rj−d раздаётся пропорционально обратным массам.
- Если vn = (vi−vj)·n > 0: Jn = (1+e)·vn/(1/mi+1/mj), e = 0.94; vi −= Jn/mi·n, vj += Jn/mj·n.
- Трение шар-шар («отброс»): скорость точек контакта в плоскости ci = vi + wz_i·ri·(−ny, nx), cj = vj + wz_j·rj·(ny, −nx); s = (ci−cj) − ((ci−cj)·n)·n. Если |s| > 1e-6: Jt = min(|s|/(3.5/mi + 3.5/mj), μb·Jn), μb = 0.06; P = −Jt·ŝ; vi += P/mi, vj −= P/mj; wz_i += ri·(n×P)/Ii, wz_j += rj·(n×P)/Ij (n×P = nx·Py − ny·Px, I = 0.4·m·r²).
- Событие `ball` с Jn (для звука).

**Борт/губка** (ближайшая точка q отрезка, d = |p−q| < r, n = (p−q)/d):

- Позиционно: p = q + n·r.
- Если vn = −v·n > 0: e_c = 0.82 − 0.1·min(vn/4, 1); v += (1+e_c)·vn·n.
- Трение с учётом винта: скорость точки контакта c = v + wz·r·(ny, −nx); s = c − (c·n)·n; jt = min(|s|/3.5, μc·(1+e_c)·vn), μc = 0.18; p = −jt·ŝ; v += p; wz −= 2.5·(nx·py − ny·px)/r.
- Накат через борт: компонента ω_xy, соответствующая качению вдоль n, гасится наполовину (точка контакта выше экватора) — ω_xy −= 0.5·(ω_xy·(−ny, nx))·(−ny, nx).
- Событие `cushion`.

**Лузы:** забитый шар — `potted = true`, v = ω = 0, событие `pot`.

**Округление** итоговых позиций: `roundPos(x) = Math.round(x·1e5)/1e5` — сервер пишет в state именно их.

## 6. Правила очков (`shared/rules.ts`, чистая функция)

`resolveShot({ result, values: Map<id,value>, cueInHand })` → `{ points, foul, keepTurn, cueInHandNext }`:

- Биток забит → foul `scratch`, points = −PENALTY_SCRATCH (забитые прицельные не засчитываются, но остаются забитыми), следующий стрелок с битком «с руки» в доме.
- Биток не коснулся ни одного шара (`firstHit = -1`) → foul `noHit`, −PENALTY_NO_HIT.
- Иначе points = сумма номиналов забитых прицельных; keepTurn = points > 0.
- Таймаут удара → foul `timeout`, −PENALTY_TIMEOUT, `cueInHand` сохраняется.
- Итог раунда: `rackScore` → `onRoundEnd`, отрицательные → 0.

## 7. Сообщения (`shared/messages.ts`)

- `MSG_SHOT` (стрелок, stage aim): валидация — числа конечны; |(dx,dy)| > 1e-6 → нормировать через sqrt; power клампится в [0,1]; spin клампится по MAX_TIP_OFFSET; при cueInHand — cueX ≤ L/4, внутри стола с отступом r, без перекрытия шаров, иначе удар отклоняется; без cueInHand cueX/cueY игнорируются.
- `MSG_AIM` (стрелок, stage aim, ≤ AIM_MAX_PER_SEC) → `MSG_AIM_OF` остальным.
- `MSG_SHOT_PLAYED` — всем, клиент строит `createSimulation` из `balls`+параметров и проигрывает в реальном времени.

## 8. Экраны

- Один canvas на весь игровой экран, стол горизонтально (портрет → повёрнут на 90°). Деревянные борта, сукно с градиентом, ромбики, линия дома, лузы.
- Шары: тень, радиальный блик, цвет по kind (small — яркие цвета, std — синие/красные, big — бордо/изумруд, giant — фиолетовый, gold — золото с блеском), номинал на кружке, который **катится** (ориентация интегрируется по ω).
- Свой ход (aim): палец/мышь на столе задаёт направление (от битка к точке); слайдер силы, кружок точки удара (винт), кнопки тонкой доводки ◀ ▶ (0.15°), кнопка «Удар». Линия прицела с «шаром-призраком» в точке первого контакта, направление прицельного шара после удара и касательная битка (`predictFirstHit`). Кий рисуется позади битка, отводится по силе.
- Биток с руки: тянуть биток в пределах дома (подсветка дома).
- Чужой ход: прицел и кий стрелка по `MSG_AIM_OF`.
- HUD сверху: чей ход (аватар+ник), очки раскладки всех, итог прошлого удара («+5», «Фол: биток в лузе −2»), осталось шаров.
- Звук (Web Audio, без файлов): щелчок шар-шар/борт по силе импульса, «пум» лузы.
