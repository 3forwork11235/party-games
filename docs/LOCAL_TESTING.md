# Локальный запуск и тест с двух телефонов

## Один раз
```
npm i -g pnpm@10
pnpm install
```

## Запуск
```
pnpm dev demo-clicker
```
Поднимает сервер Colyseus на `0.0.0.0:2567` и Vite на `0.0.0.0:5173`. Vite печатает строки `Network: http://<IP>:5173` — нужна та, что у Wi-Fi адаптера.
Вручную по отдельности: `pnpm --filter @party/server dev` и `pnpm --filter @game/demo-clicker dev`.

## Два телефона в одной сети
1. ПК и оба телефона — в одной Wi-Fi сети (не гостевой: в ней клиенты часто изолированы).
2. Windows при первом запуске спросит доступ для Node.js — разрешить для **частных** сетей. Если окно не появилось или сеть «общественная»: Параметры → Сеть → свойства Wi-Fi → «Частная», либо разрешить входящие TCP 5173 и 2567 в брандмауэре.
3. Телефон 1: открыть `http://<IP>:5173`, ввести ник, «Создать комнату», «Пригласить» — ссылка `http://<IP>:5173/?room=XXXXX`.
4. Телефон 2: открыть ссылку (или ввести 5-символьный код), «Войти по коду».
5. Хост: «Начать». Клиент сам ходит на `ws://<IP>:2567` (тот же hostname, что в адресной строке).

Что проверить: лобби → отсчёт → раунд → итоги раунда → рекламная заглушка (после 1-го раунда, далее не чаще раза в 30 с) → итоги → «Ещё раз». Переподключение: выключить Wi-Fi на телефоне на 10–20 с во время раунда — игрок возвращается с очками.

## Через интернет (любая сеть, мобильный интернет)
В dev-режиме клиент ходит к серверу через тот же адрес (`/colyseus` проксируется Vite на :2567), поэтому наружу нужен один порт — 5173.

**Одним кликом:** `start_online.bat` (или `start_online.bat <slug>`) в корне — поднимает сервер и клиент, при необходимости открывает `tuna http 5173`, показывает https-ссылку и копирует её в буфер.

Вручную:
1. `pnpm dev demo-clicker`
2. В отдельном окне: `tuna http 5173` (или `cloudflared tunnel --url http://localhost:5173`).
3. Открыть на телефонах https-адрес, который покажет туннель. Брандмауэр и профиль сети менять не нужно.
Пока туннель открыт, игра доступна всем, у кого есть ссылка; закрыть окно туннеля после теста.

## Проверка без телефонов
Две вкладки: `http://localhost:5173` и `http://127.0.0.1:5173` (разные origin → разный localStorage → разные игроки). Фоновая вкладка браузера тормозит таймеры, поэтому кликать в той, что на переднем плане.

## Сборки
```
pnpm build:web demo-clicker
pnpm build:yandex demo-clicker
pnpm zip:yandex demo-clicker
```
Результат: `dist/web/demo-clicker`, `dist/yandex/demo-clicker.zip`. Для реального сервера сборку делать с `VITE_SERVER_URL=wss://<API_DOMAIN>`.

## Сайт на GitHub Pages
Адрес: https://3forwork11235.github.io/party-games/ (каждая игра в `/<slug>/`). Публикуется workflow `.github/workflows/pages.yml` при push в `master`; локально: `pnpm build:site`.
- Сервер: Render (бесплатный тариф, `render.yaml`) — `wss://party-games-server-ug5f.onrender.com`, обновляется сам при push в `master`. Засыпает после 15 мин простоя: первый вход после сна ~1 мин.
- Альтернатива для тестов — сервер на ноутбуке: `start_server_online.bat` (Tuna). Бесплатный Tuna показывает страницу «Посетить» и на WebSocket из браузера, поэтому для сайта на Pages работает плохо; для теста с ноутбука удобнее `start_online.bat`.
- Адрес сервера в сборке меняется переменной репозитория `SERVER_URL` (Settings → Secrets and variables → Actions → Variables); по умолчанию `wss://party-games-server-ug5f.onrender.com`. Перед релизом — VPS + домен (docker-compose.yml), меняется только эта переменная.
