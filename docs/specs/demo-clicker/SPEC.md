# SPEC: Кто быстрее (`demo-clicker`)

Демо для проверки движка: весь путь lobby → раунд → очки → межстраничная (заглушка) → итоги.

## 1. Концепция
Все одновременно жмут большую кнопку; кто первым сделает 30 нажатий — победил раунд. 3 раунда.

## 2. Игроки
2–8. Выход посреди раунда: прогресс сохраняется, может вернуться. Вход после старта — нельзя.

## 3. Фазы и тайминги
`GameConfig`: rounds 3, countdownMs 3000, roundMs 20000, roundEndMs 4000, остальное — DEFAULT.
- countdown: цифры 3-2-1 крупно, кнопка неактивна.
- round: кнопка активна, у всех видны полоски прогресса. Досрочный конец — когда все подключённые дошли до 30.
- roundEnd: scoreboard с `+N`.
- adBreak: app-shell вызывает AdManager (web — оверлей-заглушка 2 с).
- results: подиум.

## 4. Состояние и сообщения
`ClickerState extends CoreState`:
| Поле | Тип | Назначение |
|---|---|---|
| `target` | number | 30 |
| `clicks` | MapSchema<number> | playerId → нажатий в текущем раунде |
| `finishOrder` | ArraySchema<string> | playerId в порядке достижения target |

Клиент → сервер: `demo-clicker:tap` `{}` — только в фазе `round`. Сервер игнорирует нажатия сверх 20 в секунду от игрока (скользящее окно 1 с) и после достижения target. Отдельно от core rate-limit: core-бакет должен пропускать 20/с (capacity 40, refill 25 — ок).

## 5. Подсчёт очков
Место по `finishOrder`: 1-е — 3, 2-е — 2, 3-е — 1. Не дошедшие до 30 — 0. Пример: A первый, B второй, C 25 нажатий → A+3, B+2, C+0.
Чистая функция `scoreRound(finishOrder: string[]): Record<string, number>` в `shared/scoring.ts`.

## 6. Контент
`content/{ru,kk,en}.json`: `clicker.title`, `clicker.tap`, `clicker.go`, `clicker.rules`, `clicker.finished` (`Ты {place}-й!`).

## 7. Экраны
- Игровой экран (`client/game.ts`): canvas сверху (~40% высоты) — горизонтальные полоски прогресса всех игроков (аватар + ник + clicks/30, свой — подсвечен), под ним круглая кнопка Tap ≥ 160px (`pointerdown`, не `click`; `navigator.vibrate?.(5)`), таймер `@party/ui` сверху.
- Локально кнопка показывает мгновенный отклик (счётчик +1 оптимистично), истина — из state.
- Остальные экраны — из app-shell.

## 8. Монетизационные точки
Межстраничная между раундами (через app-shell). Rewarded — нет. Косметика: рамка и цвет ника на полосках.

## 9. Аналитика
Стандартные события из app-shell. Своих нет.

## 10. Критерии готовности
- [ ] `scoreRound` и лимит 20/с покрыты тестами
- [ ] Тест комнаты: 2 клиента, полный цикл 3 раундов до results с правильными очками; досрочное завершение раунда
- [ ] Две вкладки браузера: лобби → 3 раунда → реклама-заглушка между раундами → итоги → «Ещё раз»
- [ ] `build:web`, `build:yandex`, `zip:yandex` зелёные
